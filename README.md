# 🖥️ نظام المبيعات والمرتجعات — محل الكمبيوتر

برنامج بواجهة رسومية عربية (من اليمين إلى اليسار) لإدارة عمليات اليومية بنظام
الأنواع الثلاثة (نقداً / شبكة / مرتجع)، مع إغلاق يومي، أرشيف تقارير، بحث، نظام
مستخدمين **وصلاحيات دقيقة يمنحها المدير (إحدى عشرة صلاحية لكل مستخدم)**، سجل تدقيق
**تفاعلي (نقرة = فلترة)**، لوحة معلومات، وتصدير Excel — وطباعة حرارية
لتقارير اليوم (Epson TM-T20III بورق 80mm) — وطباعة A4 عبر ملفات PDF قياسية
مع نافذة معاينة قبل الطباعة — وحماية بيانات بخمس طبقات (نسخ يومية وشهرية
وخارجية وفورية + استعادة آمنة + تصدير طوارئ) — و**تحديث تلقائي صامت** من
مستودع خاص يظهر للمستخدمين كشريط أصفر بسيط وزر تحديث للمدير فقط — كل
ذلك في **ملف واحد**.

## ⚡ طريقة التشغيل

1. ثبّت Python 3.8 أو أحدث من الموقع الرسمي (python.org) — علّم خيار
   **"Add Python to PATH"** أثناء التثبيت على ويندوز.
2. ضع الملف `main.py` في أي مجلد.
3. شغّل من موجه الأوامر:

```
python main.py
```

**لتشغيل الطباعة الحرارية فقط** ثبّت المكتبات الثلاث بأمر واحد (اختياري —
البرنامج يعمل كاملاً بدونها وتظهر لك رسالة التثبيت عند الضغط على أزرار الطباعة):

```
pip install pillow arabic-reshaper python-bidi
```

**لطباعة تقارير A4 (PDF)** ثبّت مكتبة واحدة إضافية (اختياري — البرنامج يعمل
كاملاً بدونها وتظهر لك رسالة التثبيت عند الضغط على زر طباعة A4):

```
pip install reportlab
```

- عند أول تشغيل يُنشأ تلقائياً ملف قاعدة البيانات `shop.db` بجانب البرنامج.
- عند الخروج تُنشأ نسخة احتياطية `shop_backup.db` تلقائياً (ويمكن إنشاؤها في أي وقت
  من زر «نسخة احتياطية الآن» في الشريط الجانبي).
- **عند كل إغلاق يوم ناجح** تُنشأ نسخة احتياطية يومية تلقائياً في `backups/daily`
  (آخر 30 نسخة) ونسخة شهرية دائمة أول إغلاق بالشهر في `backups/monthly` —
  وفشل النسخ لا يلغي إغلاق اليوم أبداً (تحذير + تسجيل فقط).
- إذا كانت لديك قاعدة بيانات قديمة (من نسخة سطر الأوامر أو النسخ التي تحوي سعر
  التكلفة)، يرقّيها البرنامج تلقائياً عند التشغيل **دون فقدان أي عملية مسجلة**.
- عند الترقية إلى الإصدار 5: عمليات «بيع» القديمة تصبح تلقائياً «نقداً»، وتقارير
  الأيام السابقة يُعبّأ لها total_cash = total_sales و total_network = 0 —
  بلا فقدان أي بيانات.

## 📋 الشاشات

| الشاشة | الوظيفة |
|---|---|
| ➕ عملية جديدة | الصنف (قائمة تتذكر الأصناف) + الكمية + السعر + النوع (نقداً/شبكة/مرتجع)، والمبيع يُحسب لحظياً، ويقبل الأرقام العربية (٣) والفواصل (، ٫) |
| 📋 عمليات اليوم | جدول عمليات اليوم مع فلتر النوع (الكل/نقداً/شبكة/مرتجع) وفلتر البائع، المرتجعات حمر بقيم سالبة، حذف بتأكيد، وإغلاق اليوم بتقرير يفصل الدرج النقدي عن كشف جهاز الشبكة |
| 🧾 فاتورة أصناف | سلة متعددة الأصناف تُحفظ دفعة واحدة مع تصدير Excel |
| 🗂️ الأرشيف | كل التقارير المغلقة بأعمدة نقداً/شبكة منفصلين، تصفية بمدى تاريخ، نقر مزدوج للتفاصيل، وزر «⚙️ الإجراءات» الواحد يجمع: عرض التفاصيل • طباعة/معاينة A4 • طباعة حرارية • تصدير CSV/Excel • تقرير الفترة • إعادة فتح اليوم |
| 🔎 بحث | بحث جزئي في كل التاريخ + عدد النتائج والإجمالي الكلي |
| 📊 لوحة المعلومات | لمن يملك صلاحيتها: فترات سريعة + بطاقات (منها مبيعات نقداً/شبكة) + أفضل 5 أصناف + رسم بياني |
| ⚙️ إعدادات الطباعة | بصلاحيتها: قائمة طابعات ويندوز + طباعة تجريبية + اسم المحل + الطباعة التلقائية عند الإغلاق + سطر توضيحي لتقارير A4 |
| 🗄️ النسخ والاستعادة | بصلاحيتها: جدول كل النسخ (يومية/شهرية/فورية) + نسخة فورية + استعادة آمنة بفحص صحة + مجلد خارجي + تصدير طوارئ |
| 👥 إدارة المستخدمين / 📜 سجل التدقيق / 📈 تقرير أداء البائعين | إدارة المستخدمين للمدير فقط (مع منح الصلاحيات الدقيقة) — والسجل والأداء لمن يملك صلاحيتيهما |

**الشريط الجانبي** مقسّم إلى ثلاث مجموعات بعناوين فاصلة صغيرة (العمليات /
التقارير / الإدارة) — والعنوان يظهر فقط إن كان في مجموعته زر ظاهر حسب
صلاحيات المستخدم — وأسفله زر واحد كبير «👤 [الاسم] ([الدور])» يفتح قائمة
المستخدم: تغيير كلمة المرور • نسخة احتياطية الآن • تبديل المستخدم • خروج.

**الشريط العلوي** يعرض دائماً 5 بطاقات: عدد العمليات، نقداً، شبكة، المرتجعات،
والإجمالي (= نقداً + شبكة − المرتجعات).

## 🖨️ الطباعة الحرارية (تقارير اليوم فقط — بلا فواتير عملاء)

- **الإعداد (مرة واحدة):** شغّل البرنامج كمدير ← «⚙️ إعدادات الطباعة» ← اضغط
  «🔄 تحديث القائمة» ← اختر طابعتك (Epson TM-T20III) ← اكتب اسم المحل ←
  «💾 حفظ الإعدادات» ← اضغط «🖨 طباعة تجريبية» للتأكد أن كل شيء سليم.
- **عند إغلاق اليوم:** إن فعّلت «الطباعة التلقائية عند الإغلاق» يُطبع تقرير اليوم
  مباشرة بعد حفظه، وإلا يسألك البرنامج. **فشل الطباعة لا يلغي حفظ اليوم أبداً**.
- **إعادة طباعة أي يوم سابق:** من الأرشيف: حدد اليوم ثم «🖨 طباعة التقرير»
  (أو من نافذة تفاصيل اليوم) — يُطبع نفس التقرير مع سطر «إعادة طباعة» والوقت
  الحالي، ويُسجّل باسمك في سجل التدقيق.
- التقرير المطبوع: ترويسة اسم المحل ثم ===== ثم «تقرير إغلاق اليوم» + التاريخ
  واسم اليوم ووقت الإغلاق، الإحصائيات (عدد العمليات / نقداً / شبكة / المرتجعات)،
  خط فاصل، **إجمالي اليوم بخط أكبر**، «أغلق بواسطة»، وسطر الشكر.
- الإرسال أوامر ESC/POS خام مباشرة للطابعة (بلا نوافذ طباعة) مع قص الورق
  تلقائياً بعد كل تقرير، والحروف العربية متصلة تماماً كطباعة الكاشير.

## 👁️ طباعة A4 عبر المعاينة وملفات PDF (حل مشكلة الصفحات البيضاء)

- **المشكلة القديمة:** إرسال تقارير مباشرة لطابعة A4 كان ينتج صفحات بيضاء —
  **الحل الجذري:** التقارير تُنشأ الآن **ملفات PDF قياسية** تفهمها كل الطابعات.
- **نافذة «👁️ معاينة قبل الطباعة» (900×700):** تعرض التقرير كما سيُطبع تماماً
  (الترويسة والتواريخ والصفوف والإجماليات) قبل أي طباعة A4 — لا طباعة مباشرة
  بدون معاينة.
- **زر «🖨 طباعة A4 (PDF)»:** يُنشأ ملف PDF مؤقتاً (في مجلد `pdf_reports`) ثم
  يُفتح **حوار الطباعة القياسي في ويندوز** — اختر طابعة A4 منه فتختفي مشكلة
  الصفحات البيضاء نهائياً.
- **زر «🖨 طباعة حرارية 80mm»:** نفس نظام ESC/POS الموجود من نفس النافذة.
- **ماذا يُطبع عبر المعاينة:** تقرير إغلاق اليوم (نفس محتوى التقرير الحراري) —
  وإعادة طباعة أي يوم من الأرشيف (زر «🖨 طباعة/معاينة A4» في شريط الأرشيف
  وفي نافذة تفاصيل اليوم) — و«📄 تقرير الفترة A4» بعنوان «تقرير فترة من
  [تاريخ] إلى [تاريخ]» مع جدول الأيام والإجمالي التراكمي بعد فلترة مدى التاريخ.
- كل طباعة A4 تُسجل في سجل التدقيق بصيغة «طباعة A4 — [نوع التقرير]».
- يتطلب: `pip install reportlab` (وغيابها لا يوقف البرنامج — رسالة تثبيت فقط).

## 🛡️ حماية البيانات — خمس طبقات

1. **نسخة يومية تلقائية:** بعد كل «إغلاق يوم» ناجح مباشرة تُنسخ القاعدة إلى
   `backups/daily/backup_التاريخ.db` — يُحتفظ بآخر 30 فقط (حذف الأقدم تلقائياً)،
   وفشل النسخ لا يلغي إغلاق اليوم أبداً (رسالة تحذير + error_log فقط).
2. **نسخة شهرية دائمة:** أول إغلاق في الشهر يُنشئ `backups/monthly/monthly_الشهر.db`
   — **لا تُحذف أبداً**.
3. **مجلد خارجي ثانوي:** من شاشة النسخ اختر فلاش/قرصاً خارجياً — كل نسخة يومية
   وشهرية تُنسخ في المكانين معاً، وإن فشل الخارجي تستمر الداخلية مع تحذير.
4. **شاشة «🗄️ النسخ والاستعادة»** (مدير فقط): جدول بكل النسخ (النوع/الاسم/
   التاريخ/المكان/الحجم KB/عدد العمليات داخل النسخة) + «📋 نسخة فورية الآن»
   (آخر 10) + «♻️ استعادة نسخة مختارة»: فحص صحة النسخة ← تحذير قوي مزدوج ←
   نسخة أمان تلقائية `pre_restore_...` ← استبدال آمن ← رسالة إعادة التشغيل.
5. **«📤 تصدير كل البيانات (طوارئ)»:** ملف Excel متعدد الأوراق (العمليات /
   التقارير اليومية / المستخدمون / سجل التدقيق) بلا مكتبات خارجية إضافية.

كل إجراء (نسخ/استعادة/تغيير مجلد خارجي) يُسجل في سجل التدقيق باسم المستخدم.

## 🔑 الصلاحيات الدقيقة + التحسينات التفاعلية السبع (الإصدار 8)

### 1) نظام صلاحيات دقيق يمنحها المدير
- **إحدى عشرة صلاحية** لكل مستخدم يحددها المدير بمربعات اختيار عند إضافة
  المستخدم أو تعديله لاحقاً بزر «✏️ تعديل الصلاحيات» في شاشة إدارة
  المستخدمين:
  إضافة عمليات وفواتير • إغلاق اليوم • حذف عملية • ✏️ تصحيح عملية (الإصدار
  18) • إعادة فتح يوم مغلق •
  عرض سجل التدقيق • لوحة المعلومات • تقرير أداء البائعين • النسخ والاستعادة •
  إعدادات الطباعة • تصدير التقارير (CSV/Excel/PDF).
- **المدير يملك كل الصلاحيات دائماً** وتظهر له مقفلة — والبائع الجديد
  الافتراضي: «إضافة عمليات وفواتير» فقط.
- أزرار الشريط الجانبي وشاشاته تُبنى حسب صلاحيات المستخدم الفعلية عند كل
  دخول/تبديل — وكل منح/سحب يُسجل في سجل التدقيق (من أعطى/سحب ماذا ومن).
- الترقية آمنة بلا فقد بيانات: البائعون الحاليون يحصلون تلقائياً على
  الصلاحية الافتراضية (إضافة العمليات فقط).

### 2) سجل تدقيق تفاعلي (تفصيل بالنقر)
- النقر على أي صف يعرض **سجلات هذا المستخدم فقط**، والنقر على عمود
  «الإجراء» يعرض **هذا الإجراء فقط** (كل من حفظ فاتورة مثلاً).
- سطر ملون فوق الجدول يوضح الفلتر النشط وعدد السجلات، وزر «👁 عرض الكل»
  يعيد الجدول كاملاً، وقائمة «الإجراء» المنسدلة تختصر الفلترة الشائعة.
- الفلترة عرضية في الذاكرة فقط ولا تمس قاعدة البيانات.

### 3) تسجيل الدخول بقائمة منسدلة
- حقل اسم المستخدم قائمة منسدلة بكل **المستخدمين المفعّلين** (المدير أولاً
  ثم الباقي أبجدياً) — رسائل الخطأ الثلاث ومحاولات الدخول الفاشلة كما هي.

### 4) تبديل المستخدم يغلق كل النوافذ
- كل نافذة تُفتح (تفاصيل اليوم، المعاينة، إدارة المستخدمين، تغيير كلمة
  المرور، تعديل الصلاحيات...) تُسجل في تتبع مركزي — وعند «🔄 تبديل المستخدم»
  تُغلق كلها فوراً مع إفراغ السلة (تحذير السلة باقٍ كما هو)، ويُسجل:
  «تبديل مستخدم — إغلاق [عدد] نافذة مفتوحة» — فلا تبقى أي شاشة تعمل
  باسم المستخدم القديم أبداً.

### 5) دمج أزرار الأرشيف في زر إجراءات واحد
- أسفل شاشة الأرشيف زر واحد «⚙️ الإجراءات» يفتح قائمة منسدلة بكل الخيارات
  (عرض التفاصيل / طباعة A4 / طباعة حرارية / تصدير CSV / تصدير Excel /
  تقرير الفترة / إعادة فتح اليوم) — ونفس المبدأ في نافذة تفاصيل اليوم —
  كل خيار ينفذ نفس الدالة الموجودة دون تغيير، وخيارات التصدير وإعادة الفتح
  تظهر بحسب الصلاحيات.

## 🔐 نافذة تسجيل الدخول المحسّنة (الإصدار 9) — 8 ميزات بصرية وتفاعلية

شكل جديد لنافذة الدخول فقط (420×520 بلا إطار ويندوز تُسحب من أي مكان على
الخلفية بزر ✕ أعلى اليسار يغلق البرنامج كما عند إلغاء الدخول) — بنفس
منطق التحقق القديم حرفياً: نفس رسائل الخطأ الثلاث، نفس تسجيل المحاولات
الفاشلة في سجل التدقيق، نفس شرط active=1، ونفس شاشة إنشاء المدير أول
مرة — وتبدو في وضعين: **تدرج كحلي داكن** أو **صورة المحل بطبقة داكنة**.

### 1) زر عين 👁 لكلمة المرور
- زر صغير داخل الحقل (على يساره) في نافذة الدخول وشاشة إنشاء المدير
  ونافذة تغيير كلمة المرور: 👁 عند الإخفاء و🙈 عند الإظهار، ويعود
  للإخفاء تلقائياً بعد 5 ثوانٍ.

### 2) زر دخول يتفاعل بصرياً
- زر عريض بعرض البطاقة بلون ACCENT: يفتح درجة عند مرور المؤشر، ويغمق
  لحظة الضغط 150 مللي ثم يعود، ويتوقف عن الاستجابة تماماً أثناء التحقق.

### 3) تذكر آخر مستخدم
- بعد كل دخول ناجح يُحفظ الاسم في settings (المفتاح last_user) وتُعبّأ
  به القائمة المنسدلة عند الفتح التالي والمؤشر جاهز في حقل كلمة المرور.

### 4) شريط قوة كلمة المرور عند التعيين
- في شاشة إنشاء المدير ونافذة تغيير كلمة المرور: شريط ملون يتحدث مع كل
  ضغطة مفتاح (أحمر أقل من 5 أحرف / برتقالي 5+ / أخضر 6+ وفيها رقم) مع
  نص إرشادي «ضعيفة / متوسطة / قوية» — والضعيفة جداً تمنع الحفظ برسالة
  عربية واضحة.

### 5) اهتزاز البطاقة عند الخطأ
- عند كلمة مرور خاطئة أو حساب موقوف: البطاقة تهتز أفقياً نصف ثانية
  ويعود لحاله، وحقل كلمة المرور يلتون بإطار أحمر قصير — ورسالة الخطأ
  النصية تبقى معهما.

### 6) حالة «جارٍ التحقق...»
- نص الزر يتغير ويتعطل الزر ويُمنع الضغط المزدوج، مع انتظار 400 مللي
  قبل عرض النتيجة بإحساس طبيعي — والدخول الناجح يكمل فوراً بعدها.

### 7) ظهور تدريجي عند الفتح
- تلاشٍ قصير: شفافية ترتفع إلى 1.0 خلال ~300 مللي مع انزلاق البطاقة من
  الأسفل للأعلى — ولو لم يدعم النظام الشفافية تُتجاهل بهدوء (try/except).

### 8) صورة خلفية للمحل (اختيارية للمدير)
- في شاشة إعدادات الطباعة زر «🖼 اختيار صورة الخلفية» (png/jpg تُحوّل
  تلقائياً عبر pillow وتُحفظ باسم login_bg.png ثابتاً في مجلد البيانات
  ومسارها في settings بالمفتاح login_bg) — تُعرض خلف بطاقة الدخول بطبقة
  داكنة شفافة فوقها حتى تبقى الحقول واضحة، وزر «🗑 إزالة الصورة» يعيد
  الخلفية المتدرجة الافتراضية — وأي فشل (حذف/تالفة) يُتجاهل بهدوء.
- التعيين والإزالة يُسجلان في سجل التدقيق، واسم المحل يظهر شعاراً نصياً

## 🔧 مشاكل وحلول (نافذة تُغلق فوراً؟)

البرنامج محصّن الآن: أي عطل يظهر **صندوق خطأ عربي واضح** ويُسجَّل في
`error_log.txt` بجانب البرنامج — لن ينهار بصمت بعد الآن.

| الحالة | الحل |
|---|---|
| شغّلته من **داخل ملف ZIP** | استخرج الملفات إلى مجلد عادي أولاً ثم شغّل — بايثون لا يعمل من داخل ZIP |
| رسالة **database is locked** | نسخة أخرى من البرنامج لا تزال مفتوحة — أغلقها كلها وأعد المحاولة |
| **shop.db قديم أو تالف** | يُحفظ تلقائياً باسم `shop.db.tainted-التاريخ` ويبدأ البرنامج بقاعدة جديدة |
| التشغيل من **Program Files** بلا صلاحية كتابة | انقل البرنامج لمجلد عادي، أو انقل `shop.db` بجانبه — والبرنامج يتراجع تلقائياً لمجلد بيانات المستخدم |
| تكراش عند الطباعة/التصدير فقط | راجع نهاية `error_log.txt` — آخر سطر فيه هو السبب الدقيق |
| زر الطباعة يعرض رسالة تثبيت | المكتبات الثلاث غير مثبتة: `pip install pillow arabic-reshaper python-bidi` ثم أعد التشغيل |
| زر «طباعة A4» يعرض رسالة تثبيت | مكتبة reportlab غير مثبتة: `pip install reportlab` |
| «تعذر فتح حوار الطباعة تلقائياً» | فُتح ملف PDF بدلاً منه — اطبعه منه مباشرة (Ctrl+P) واختر طابعة A4 |
| «المجلد الخارجي غير متوفر» عند الإغلاق | القرص/الفلاش الخارجي مفصول — النسخ الداخلية سليمة، أوصل القرص وحدّث المجلد من شاشة النسخ |
| «فشل الطباعة — الطابعة غير موصولة» | تأكد من كابل الطابعة والكهرباء وأنها مثبتة في ويندوز، ثم أعد اختيارها من إعدادات الطباعة |

> عند أي مشكلة: افتح `error_log.txt` الموجود بجانب البرنامج وأرسل آخر سطر منه —
> هو الذي يحدد السبب بدقة.

## 🪟 تخطيط النوافذ + 🔄 التحديث بالموافقة الصريحة (الإصدار 15)

**الجزء الأول — القاعدة الذهبية لكل النوافذ المنبثقة**: أزرار أي نافذة
منبثقة لم تعد تُقص أبداً مهما طال محتواها أو صغرت الشاشة. القاعدة الموحدة:
شريط الأزرار السفلي يُحزم أولاً `side="bottom"` قبل أي شيء آخر، ثم العنوان،
ثم الجدول/المحتوى يتمدد `fill="both" expand=True` في المساحة الباقية.
دالة موحدة جديدة `place_window` تُطبق في نهاية بناء كل نافذة: تمركز وسط
الشاشة دائماً، واحترام الشاشات الصغيرة (النافذة = الشاشة − 80 بكسل كحد
أقصى)، وفحص ذاتي: إن طلب المحتوى ارتفاعاً أكبر تُرفع الأبعاد تلقائياً.

الأحجام الجديدة: أرشيف الإصدارات **900×640 + minsize + تمدد كامل** (كان
780×520 بلا تمدد فكانت أزراره السفلية مقصوصة — العدّاد صار فوق شريط
الأزرار مباشرة)، تفاصيل اليوم 1010×660 + تمدد، سلة المحذوفات 1000×620 +
تمدد، المعاينة قبل الطباعة 900×700 + minsize، ونوافذ النماذج (تغيير
كلمة المرور / إضافة مستخدم / تعديل الصلاحيات / إعادة التعيين / بدء يوم
جديد / حوار تبديل يوم العمل) ارتفاعها من المحتوى ذاته دائماً مع زر الحفظ
محزوماً أسفل البطاقة أولاً. نافذة «عن البرنامج» كما كانت 420×560 لكن
بالفحص الذاتي الموحد. الشاشات الخمس الأخرى المذكورة في الطلب (إدارة
المستخدمين، سجل التدقيق، تقرير الأداء، النسخ والاستعادة، إعدادات الطباعة)
صفحات داخل النافذة الرئيسية القابلة للتحجيم أصلاً (minsize 950×620) لا
نوافذ منبثقة — فلم تُمس التزاماً بقاعدة عدم المساس بالموجود.

**الجزء الثاني — التحديث بالإعلام والموافقة الصريحة**: ثلاث بوابات متتابعة
قبل أي تثبيت: (1) الشريط الأصفر إعلام فقط كما كان، (2) نافذة الموافقة
الجديدة تعرض «الإصدار الحالي [رقم] ← الجديد [رقم]» + زر «📄 ما الجديد؟»
يعرض ملاحظات الإصدار إن نُشرت + سطر الطمأنة، ولا يبدأ التنزيل إلا بزر
«✅ نعم، ثبّت التحديث الآن» الصريح — و«❌ لا، لاحقاً» أو إغلاق النافذة لا
يفعلان شيئاً ويبقى الشريط للموافقة لاحقاً، (3) إن كانت السلة فيها أصناف
غير محفوظة يُعطَّل زر التثبيت داخل النافذة حتى تأكيد تحذير «السلة فيها
[عدد] أصناف — ستُفقد. متابعة؟» (نفس منطق تبديل المستخدم). الفحص الدوري
واليدوي يجلبان رقم الإصدار فقط ولا ينزّلان ملف البرنامج أبداً — التنزيل
يبدأ فقط لحظة الموافقة الصريحة.

**إعادة التشغيل التلقائية بعد التثبيت الناجح**: رسالة «✅ تم التحديث إلى
[رقم] بنجاح! جارٍ إعادة تشغيل البرنامج تلقائياً... (سيُطلب تسجيل الدخول
من جديد)» ثم الترتيب الآمن: إطلاق العملية الجديدة أولاً
`subprocess.Popen([sys.executable, مسار البرنامج])` ثم الخروج النظيف بنفس
مسار `exit_app` القائم (النسخة الاحتياطية والتدقيق كاملان) — فلا تظهر لحظة
«لا برنامج مفتوح» ولا تتضارب النسخ. الحمايات: فشل الإطلاق = رسالة «أعد
فتح البرنامج يدوياً هذه المرة فقط» وخروج عادي بلا انهيار، ونسخة EXE تبقى
على الرسالة اليدوية. لا تُمس القاعدة ولا النسخ الاحتياطية ولا الإعدادات
ولا سجل التدقيق ولا الأرشيف إطلاقاً — يُفقد تسجيل الدخول فقط. كل إجراء
في سجل التدقيق: إعلام الفحص (كما كان) + موافقة + رفض + تثبيت + إعادة
تشغيل.

## 🛡️ إغلاق ثغرات الغش + 🔐 التحصين التقني (الإصدار 16)

**1️⃣ ربط المرتجع بعملية البيع الأصلية (إغلاق أكبر ثغرة غش)**: عند اختيار
«مرتجع» في شاشة عملية جديدة أو فاتورة الأصناف يظهر صف إلزامي «العملية
المُرجَعة» — قائمة بعمليات البيع الصالحة (نفس الصنف، نقداً/شبكة، الأحدث
أولاً) بالصيغة `[رقم] — [التاريخ] — كمية [المتبقي] — بـ [السعر] — [النوع]`
حيث الكمية المعروضة هي المتبقي الصالح للإرجاع بعد خصم المرتجعات السابقة.
ممنوع مرتجع بلا أصل (رسالة عربية واضحة)، والكمية لا تتجاوز المتبقي،
والسعر يُعبأ بسعر الأصل تلقائياً ويُقفل للتعديل — مرتجع بسعر مختلف
مستحيل. كل مرتجع يخزن رابطه في العمود الجديد `original_op_id`، وفي جداول
عمليات اليوم وتفاصيل الأرشيف والبحث يعرض صف المرتجع بجانبه «↩ مرجع:
[رقم الأصل]» (والمرتجعات القديمة قبل الإصدار تعرض «—» وتعمل كما كانت بلا
أي منع رجعي). في الفاتورة: كل صنف مرتجع بالسلة يُربط بأصله، والمتاح
يخصم أيضاً ما أُضيف للسلة على نفس الأصل، وتحقق نهائي قبل الحفظ يحمي من
تغيّر البيانات بين الإضافة والحفظ. رابط الأصل يحفظ مع المرتجع في سلة
المحذوفات ويُستعاد معه — فلا يضيع الربط بالحذف والاستعادة.

**2️⃣ لوحة تنبيهات الإدارة**: بعد دخول المدير/الأدمن مباشرة فحص صامت
لإحصاءات آخر 7 أيام من سجل التدقيق (عدد الحذف، إعادة فتح يوم، الاستمرار
بعد منتصف الليل، محاولات الدخول الفاشلة). إن وُجد نشاط يستحق المراجعة
(حذف واحد أو إعادة فتح واحدة أو أكثر من محاولتَي دخول فاشلتين) ظهرت
بطاقة أعلى لوحة المعلومات: «⚠ نشاط يستحق المراجعة (آخر 7 أيام): [عدد]
حذف — [عدد] إعادة فتح يوم — [عدد] محاولات دخول فاشلة» بأصفر للخطورة
العادية وأحمر للخطورة العالية، مع زر «📋 عرض التفاصيل» يفتح سجل التدقيق
مصفلاً على هذه الأنواع، وزر «✖ إخفاء» جلسي فقط. بلا نشاط حساس: صمت
تام لا يظهر شيء — والبائع لا يرى البطاقة أبداً.

**3️⃣ التوقيع التسلسلي لسجل التدقيق**: كل سجل تدقيق جديد يحمل بصمة
`sha256(السجل السابق كاملاً + بصمته + بيانات السجل الجديد)` في العمود
الجديد `prev_hash` — سلسلة متسلسلة يكسرها أي حذف أو تعديل يدوي على
القاعدة خارج البرنامج. زر «🧪 فحص سلامة السجل» في شاشة التدقيق
(مدير/أدمن) يعيد حساب السلسلة كاملة: السليمة تعرض «✅ سجل التدقيق سليم
وغير معدل» بالأخضر، والمكسورة «⚠ عبث بالسجل عند: [السجل]!» بالأحمر مع
تحديد السجلات المكسورة داخل الجدول نفسه — واقتطاع نهاية السلسلة يكشفه
طرف محفوظ في الإعدادات. السجلات القديمة قبل الإصدار بداية السلسلة بلا
كسر، وكل فحص يُسجل في التدقيق.

**4️⃣ وضع WAL للقاعدة**: `journal_mode=WAL` + `synchronous=NORMAL`
عند كل اتصال — أمان الكتابة عند انقطاع الكهرباء وسرعة أكبر، وقبل أي
نسخ مباشر عن ملف القاعدة (النسخ التلقائية ونسخة الخروج) تُوحّد الملف
بـ`wal_checkpoint(TRUNCATE)` فلا تنقص النسخة آخر الكتابات أبداً.

**5️⃣ فهارس التسريع**: `idx_ops_date` و`idx_ops_item` و`idx_ops_seller`
و`idx_audit_at` — تُبنى مرة واحدة وبلا أي تغيير على أي استعلام قائم.

**6️⃣ مراقبة بصمة كود البرنامج**: عند أول تشغيل تُحفظ بصمة `sha256`
لمحتوى ملف البرنامج في الإعدادات، وعند كل إقلاع (قبل شاشة الدخول وبصمت
وسرعة) تُقارن: المطابق يمر بلا أثر، والمعدل يدوياً خارج نظام التحديث
تظهر له شاشة تحذير حمراء كاملة: «⛔ تم تعديل ملف البرنامج خارج نظام
التحديث! هذا غير مسموح لأسباب أمنية» — لا يمر منها إلا بزر «أنا المالك
— اعتماد التعديل» بكلمة سر الأدمن (تُحدّث البصمة ويُسجل بالتدقيق) أو
زر «خروج». التحديث عبر نظام GitHub يحدّث البصمة تلقائياً قبل إعادة
التشغيل فلا تظهر الشاشة بعد أي تحديث نظامي — ونسخة EXE خارج الفحص.

**7️⃣ ضغط النسخ الاحتياطية**: النسخ اليومية والفورية تُحفظ مضغوطة zip
بنفس الأسماء + لاحقة `.zip` (والشهرية تبقى `.db` دائمة كما هي)،
والاستعادة تفك وتفحص ثم تستبدل — مع توافق خلفي كامل: النسخ القديمة
`.db` تُستعاد مباشرة كما كانت، وعدّاد المساحة في شاشة النسخ يعرض الحجم
الفعلي بعد الضغط.

**8️⃣ فحص سلامة القاعدة**: زر «🧪 فحص سلامة قاعدة البيانات» في شاشة
النسخ والاستعادة يشغّل `PRAGMA integrity_check` ويعرض النتيجة بالعربية:
سليمة ✅ أو تالفة ⚠ مع التفاصيل ونصيحة الاستعادة. (حقل التوكن لا وجود
له في أي واجهة أصلاً — التوكن ثابت في الكود لا يظهر نصاً في أي شاشة
ولا يُسجل في أي لوج كما كان.)

**الإضافة 3 — شاشة تسجيل الدخول بملء الشاشة 🖥️**: نافذة الدخول تفتح بملء
الشاشة (`state("zoomed")` على ويندوز مع geometry بأبعاد الشاشة كبديل —
الفشل يُتجاهل بهدوء فيظهر الحجم العادي). الخلفية (صورة المحل أو التدرج
الكحلي) تمتد على كامل الشاشة، والبطاقة الوسطية تبقى بحجمها في المنتصف،

بخط كبير (للتحقق من تاريخ الجهاز صباحاً)، وأسفل يسار الإصدار وحالة قاعدة
البيانات (🟢 متصلة / 🔴 مشكلة). كل ميزات الدخول الحالية باقية كما هي
بالضبط (العين 👁 وشريط قوة كلمة المرور والاهتزاز و«جارٍ التحقق» والظهور

حماية الشاشة: Alt+F4 وEsc يتحولان لتحذير «أكمل تسجيل الدخول» — والخروج
الوحيد دخول ناجح أو زر ✕ (يغلق البرنامج كاملاً كالسلوك القائم عند
الإلغاء)، وtopmost أثناء الدخول فقط، والنافذة الرئيسية بعد الدخول بحجمها

الجاري. الانتقال الذكي عند بدء التشغيل يعمل بالحد الفجري: قبل 05:00
ويوم الأمس مفتوح = دخول عادي بلا أي سؤال (ما نزال داخل يومه حتى 05:00

## 🔧 إصلاح شريط الفاتورة + ✏️ تصحيح العمليات + 🖥️ ملء الشاشة للنافذة الرئيسية (الإصدار 18)

جولة إصلاح ثلاث مشاكل عملية — بلا أي مساس بأي شيء يعمل خارجها، وبلا أي
تغيير على قاعدة البيانات:

**المشكلة 1 — زر حفظ الفاتورة كان مفقوداً بصرياً 💾**: شريط إجراءات صفحة
الفاتورة كان يُحزم آخر شيء بعد جدول السلة المتمدد، والمساحة المطلوبة
للصفحة أكبر من المتاح في النافذة — فلا يُخصص للشريط أي مساحة إطلاقاً
ويختفي زر الحفظ كلياً (سلة فخ). أُعيد بناء الشريط ليُحزم `side="bottom"`
أولاً (قاعدة الأزرار المثبتة) قبل النموذج والجدول، فصار الزران
**[💾 حفظ الفاتورة كاملة]** (أخضر بارز) **[🗑 إزالة المحدد من السلة]**
مثبتين أسفل الصفحة دائماً مهما طال الجدول أو صغرت الشاشة. كما أُصلح مصدر
تاريخ الحفظ: الفاتورة كانت تُحفظ بتاريخ الجهاز (`today_str`) — صارت تُحفظ
**بتاريخ يوم العمل التجاري المفتوح** مطابقةً لسلوك حفظ عملية جديدة، مع
رسائل واضحة تمنع الحفظ مع سلة فارغة أو يوم مغلق أو لا يوم مفتوح. مسار
السلة كامل يعمل الآن: إضافة ← تعديل/إزالة ← حفظ ← العمليات تظهر في
عمليات يوم العمل والشريط العلوي يتحدث، مع سؤال تصدير Excel والتدقيق.

**المشكلة 2 — تصحيح عمليات يوم العمل ✏️ (تعديل حقيقي بماضٍ لا يُمحى)**:
صلاحية جديدة «✏️ تصحيح عملية» في صندوق الصلاحيات (افتراضياً مدير وأدمن
فقط — والمدير يمنحها لبائع موثوق من شاشة الصلاحيات القائمة) + زر «✏️
تصحيح العملية المحددة» في شريط عمليات اليوم يظهر لمن يملكها فقط ويتكيف
مع تبديل المستخدم. يعمل على عمليات اليوم المفتوح حصراً (يوم مغلق: رسالة
«أعد فتح اليوم أولاً من الأرشيف»). نافذة التصحيح بحقول العملية معبأة
(الصنف/الكمية/السعر/النوع/العميل) وقيود المرتجع المحفوظة: سعر المرتجع
المربوط مقفول بسعر الأصل، وكميته ضمن المتبقي، والربط لا ينكسر أبداً —
وعملية بيع عليها مرتجعات مربوطة يُقفل صنفها ولا تنزل كميتها دون مجموع
مرتجعاتها. الحفظ بالتسلسل الصارم: **(1)** الأصل يُنسخ كاملاً إلى سلة
المحذوفات بوسم «تصحيح — الأصل [#id]» **(2)** العملية تُحدَّث بنفس رقمها
(فلا ينكسر أي ربط) **(3)** سجل التدقيق يوثق كل تغيير قبل→بعد:
«تصحيح عملية [#id] بواسطة [اسم]: الكمية 2→5، السعر 15→12» **(4)** الشريط
العلوي وجدول اليوم يتحدثان فوراً.

**المشكلة 3 — النافذة الرئيسية بملء الشاشة 🖥️**: بعد الدخول تفتح النافذة
الرئيسية بملء الشاشة بنفس أسلوب شاشة الدخول القائم (`state("zoomed")`
على ويندوز مع geometry بأبعاد الشاشة كبديل — والفشل الهادئ يبقي الحجم
المعتاد)، مع minsize معقول 1000×600 حتى لا تتكسر العناصر. كل الصفحات
تتكيف تلقائياً مع المساحة الأكبر (الجداول expand والشريط الإحصائي
والأشرطة تتمدد بعرض النافذة) — والنوافذ المنبثقة تبقى بأحجامها المنطقية.

## 🖨️ التثبيت التلقائي لمكتبات الطباعة + 📡 كشف الطابعة تلقائياً (الإصدار 19)

جولة الأجهزة الجديدة — كل جهاز يُحدَّث إلى هذه النسخة صارت الطباعة تعمل
عليه **بلا أي خطوة يدوية إطلاقاً**: المكتبات الناقصة تُثبَّت بنقرة زر،
والطابعة تُختار وتُحفظ تلقائياً — بلا أي مساس بمنطق الطباعة نفسه أو
تنسيق التقارير المطبوعة، وبلا أي تغيير على قاعدة البيانات:

**القسم 1 — التثبيت التلقائي للمكتبات ⚙️**: دالة `check_print_libs()`
تفحص الثلاثة معاً (pillow + arabic-reshaper + python-bidi) بحمل محمول —
تُستدعى مرة عند بدء التشغيل صمتاً (النتيجة تُخزَّن بالذاكرة) وعند كل محاولة
طباعة، وبعد التثبيت داخل نفس العملية يُفرَّغ كاش الاستيراد
(`importlib.invalidate_caches`) كي يرى المفسِّر الحزم المثبتة للتو قبل
التحققق الفعلي بإعادة الاستيراد. **نافذة التثبيت التلقائي** حلّت محل رسالة
«الطباعة غير متاحة» القديمة في نفس مكانها ومنطقها تماماً (محاولة طباعة
بمكتبات ناقصة = لا طباعة ويرجع False) — والجديد أنها تعرض: «مكتبات الطباعة
غير مثبتة على هذا الجهاز / التثبيت تلقائي الآن؟ (يحتاج إنترنت — أقل من
دقيقة) / بعد التثبيت سيعاد تشغيل البرنامج تلقائياً وتعمل الطباعة» بزرين
أخضر **[⚙️ تثبيت تلقائي الآن]** و**[لاحقاً]** (اختيار «لاحقاً» لا يكرر
النافذة إلا عند محاولة طباعة جديدة فقط). التنفيذ من نفس بايثون البرنامج
حرفياً (`subprocess.run([sys.executable, "-m", "pip", "install", ...],
capture_output)`) بسقف أمان 5 دقائق، وفشل المسار العادي يعيد المحاولة
تلقائياً بـ`--user` قبل إعلان الفشل، وبعد النجاح يُتحقق فعلاً بإعادة
الاستيراد فتظهر «✅ تم التثبيت! جارٍ إعادة التشغيل...» وتُنفَّذ إعادة
التشغيل بنفس آلية نظام التحديث القائمة حرفياً (Popen أولاً ثم خروج نظيف
عبر exit_app) — والطباعة تعمل مباشرة بعدها. الفشل (لا إنترنت/صلاحيات):
سبب عربي واضح + **الأمر اليدوي جاهز للنسخ** بزرار 📋 نسخ، والبرنامج يستمر
عادي. وكل نتيجة تُسجَّل في سجل التدقيق: «تثبيت تلقائي لمكتبات الطباعة»
نجاح/فشل. وعند بدء التشغيل والمكتبات ناقصة: **شريط أصفر رفيع** (كشريط
التحديث) «🖨 مكتبات الطباعة غير مثبتة — انقر للتثبيت التلقائي» للمدير
فقط، وزره يفتح نفس النافذة فيُثبَّت من البداية دون انتظار أول طباعة —
وملاحظة بدء التشغيل القديمة (بأمر pip اليدوي) استُبدلت بهذا النظام.

**القسم 2 — كشف الطابعة تلقائياً 📡**: عند بدء التشغيل وعند كل محاولة
طباعة، إن كان `printer_name` فارغاً أو الطابعة المحفوظة غير موجودة بقائمة
طابعات ويندوز (فُكّت أو تغيّر اسمها): يُبحث أولاً عن اسم يحوي EPSON أو TM-
أو POS أو Receipt (أول تطابق) ثم **الطابعة الافتراضية في ويندوز**
(`GetDefaultPrinterW`) — ويُحفظ الاختيار في الإعدادات تلقائياً مع رسالة
خضراء صغيرة مرة واحدة «✅ تم اختيار الطابعة تلقائياً: [الاسم]» وتسجيل
«كشف طابعة تلقائي» بالتدقيق. لا طابعات مثبتة أصلاً: رسالة واضحة مرة
واحدة فقط «لا توجد طابعة مثبتة على هذا الجهاز — ثبّت تعريف الطابعة أولاً
من الشركة المصنعة» (لا تكرار الإزعاج). **الكشف يملأ الفراغ ويصلح المفقود
فقط ولا يتجاوز اختيار المدير اليدوي أبداً** — والإعداد اليدوي بشاشة
«⚙️ إعدادات الطباعة» باقٍ كما هو سيد الموقف.

> ⚠️ **تصحيح ضروري معلن (الإصدار 20)**: القسم 2 أعلاه كما سُلّم في جولة 19
> — ثم **استُبدل سلوكه بالكامل** في الإصدار 20 بقرار المالك: الكشف التلقائي
> أُلغي (من بدء التشغيل ومن بوابة الطباعة) وحلّ محله **اختيار صريح لكل
> جهاز** (مفتاح `printer_device_<اسم الجهاز>`) — بلا طابعة افتراضية كبديل
> تلقائي أبداً وبلا أي ملء تلقائي: انظر قسم الإصدار 20 أدناه. الدوال نفسها
> (`auto_detect_printer` و`get_default_printer`) باقية بالكود بلا حذف.

**السيناريو المستهدف 🎯** (موثق بتعليق بالكود): جهاز جديد ثُبّت عليه
البرنامج → التحديث التلقائي يوصله بأحدث نسخة → أول فتح: الفحص الصامت
للمكتبات + الشريط الأصفر للمدير + كشف الطابعة → **الطباعة تعمل على ذلك
الجهاز فوراً بلا أي خطوة يدوية إطلاقاً**.

## 🖨️🔒 فصل «اختيار الطابعة» عن «استخدام الطباعة» + طابعة خاصة بكل جهاز (الإصدار 20)

قرار الإدارة الجديد: **الطباعة عمل يومي لكل الأدوار بما فيهم البائع**،
بينما **اختيار الطابعة إعداد للجهاز يقتصر على الإدارة (أدمن/مدير)** —
ولكل جهاز من أجهزة المحل طابعته الخاصة المستقلة تماماً (فوضع المحل
يتشارك القاعدة، وتغيير طابعة جهاز لا يؤثر على بقية الأجهزة أبداً):

**1) حفظ على مستوى الجهاز 🖥️**: اختيار الطابعة يُحفظ في جدول settings
الموجود بمفتاح فريد لكل جهاز: `printer_device_` + اسم الجهاز من
`socket.gethostname()` — دوال جديدة: `device_printer_key()` و
`get_device_printer()` و`set_device_printer()`. والقراءة قبل أي طباعة
بالترتيب الصارم: مفتاح هذا الجهاز أولاً ← فإن لم يوجد فالمفتاح العام
القديم `printer_default` ← ثم `printer_name` (الذي كانت الإصدارات
السابقة تحفظ عليه فعلاً — فحُفظ توافق كامل مع الإعدادات المحفوظة) ←
فإن لم يوجد أي منهما فهذه «لا طابعة مختارة لهذا الجهاز».

**2) نافذة الاختيار للإدارة فقط 🔒**: منطق اكتشاف الطابعات المثبتة في

**3) الطباعة لكل الأدوار 🖨️**: أزرار الطباعة الحرارية (تقرير اليوم من

**للجميع بلا أي شرط صلاحية** — والبرنامج يقرأ طابعة هذا الجهاز من مفتاح
`printer_device_<hostname>` ويطبع عليها مباشرة دون فتح أي نافذة اختيار.
إن لم توجد طابعة مختارة لهذا الجهاز: رسالة عربية واضحة «لم يتم اختيار
طابعة لهذا الجهاز بعد. الرجاء التواصل مع المدير لاختيار الطابعة.» ولا
تُفتح نافذة الاختيار للبائع. **ممنوع استخدام الطابعة الافتراضية من
ويندوز كبديل تلقائي** — بدون اختيار صريح لا تحدث طباعة صامتة خاطئة

ومن بوابة الطباعة (الدوال نفسها باقية بلا حذف)، وتقارير A4/PDF عبر
reportlab كما هي تماماً (مصدر اسم الطابعة الحرارية وحده هو المتغير).

## 🌅 الإغلاق التلقائي الصارم + 🗓️ حركات الأيام السابقة + 🛠️ إصلاح المدموج + ✏️ تعديل الحركات (الإصدار 21)

**العطل المبلّغ عنه وأُصلح**: «اليوم التجاري لا يُغلق إطلاقًا مهما طال عمل
البرنامج، ونتيجة لذلك دُمجت مبيعات يومين في يوم واحد» — الإصلاح بنظام إغلاق
تلقائي صارم لا يمكن تجاوزه، مع الحفاظ على زر الإغلاق اليدوي كخيار مبكر
اختياري لا يلغي النظام التلقائي أبداً.

**1) الدالة المركزية الوحيدة 🌅**: `get_business_day()` تحسب اليوم التجاري
الصحيح من وقت الجهاز بالقاعدة الثابتة (قبل 05:00 فجراً = تاريخ الأمس، ومنها
فما فوق = تاريخ اليوم — `BUSINESS_DAY_START_HOUR = 5` كما هو أساس كل
الحسابات)، و`ensure_business_day_current()` تقارن اليوم المحفوظ
في `settings/business_day` مع ناتجها: إن اختلفا تُغلق اليوم القديم فوراً
(إجمالياته من جدول operations نفسه — **حتى لو خلا فتُسجَّل بإجماليات
صفرية** — مع `closed_at` بنظام 24)، ثم يُفتح اليوم الجديد بوضع ناتج
`get_business_day()` **دون أي تدخل من أي مستخدم**، مع تحديث كل المجاميع
والبطاقات فوراً. وتسجل في audit_log بالدالة الموقعة القائمة بنوع
`auto_close_day`، وتُظهر إشعارًا عربيًا واضحًا غير معطِّل (نافذة عابرة تختفي
بعد 10 ثوانٍ — لا تلغي ولا تعطّل أي عملية بيع جارية): «تم إغلاق يوم
[التاريخ القديم] تلقائيًا عند الساعة 05:00 وبدأ يوم تجاري جديد [الجديد]».
وبعد كل إغلاق تلقائي يُعمل نفس النسخ الاحتياطي اليومي القائم (وفشله لا يلغي
شيئاً)، والطباعة فقط إن كانت الطباعة التلقائية مفعلة وعلى طابعة مختارة
لهذا الجهاز (بلا أي نوافٍ في السياق غير المراقب).

**2) ثلاث نقاط تفتيش لا يمكن تجاوزها 🛡️**: (أ) عند بدء التشغيل قبل فتح
الشاشة الرئيسية — يغطي كون الجهاز كان مطفأ وقت الفجر، (ب) مؤقت متكرر كل
60 ثانية عبر `root.after` لا يخضع لأي صلاحية ولا يمكن لأحد إيقافه أو
تعطيله بأي إعداد (يعيد جدولة نفسه دائماً)، (ج) قبل حفظ أي عملية بيع أو
مرتجع مباشرةً (save_op وsave_invoice) — فبعد اليوم القديم لا يُسجل عليه أي
حركة إطلاقًا. واليوم المغلق لا يُفتح مرة أخرى، واليوم المفتوح بتاريخ
مستقبلي (بعد إغلاق يدوي مبكر أو بدء يدوي) لا يمسّه المؤقت إطلاقاً حتى
05:00 التالي له — نفس دلالة «الدخول الصامت» القائمة.

**3) زر الإغلاق اليدوي «🔒 إغلاق اليوم وحفظ التقرير» يبقى كما هو 📋**:
للأدمن والمدير فقط (لا يظهر للبائع نهائياً برغم أي صلاحية ممنوحة)، يعرض
تأكيداً واضحاً أن الإغلاق **سيبدأ يومًا جديدًا فورًا** مع ملخص اليوم، ثم
يستدعي نفس الدالة المركزية الوحيدة (بلا أي تكرار لمنطق الإغلاق في مكانين)
بنوع `manual_close_day` في التدقيق، وبنفس إكسسوارات الإغلاق القائمة حرفياً
(النسخ الاحتياطي ثم عرض التقرير ثم خيار الطباعة) — والمؤقت التلقائي يستمر
كالمعتاد ولا يتأثر به، والدوال القديمة close_day و_close_business_day
باقيتان بلا حذف لخدمة مسار فحص الإقلاع القائم.

الأحدث للأقدم (التاريخ، عدد الحركات، النقد، الشبكة، المرتجعات، الصافي،
وقت الإغلاق بنظام 24)، وعند اختيار يوم تُعرض كل حركاته من operations
(الوقت والصنف والكمية والسعر والإجمالي والنوع والعميل والبائع) مع **صف
إجماليات أسفل الجدول مطابق لما في daily_reports** — والربط بالآلية القائمة
(تاريخ الحركة المسجل على يوم عملها)، و«التاريخ والوقت الكاملان» لكل حركة
من مطابقة سجل التدقيق (قراءة فقط — السلسلة الموقعة لا تُمس) حيثما تُطابق

من وقتها الحقيقي بقاعدة 05:00، وينقل الحركات إلى أيامها الصحيلة (تحديث
تاريخها المسجل نفسه)، ثم يُحدّث أو يُنشئ صفوف daily_reports لكل الأيام
المتأثرة من جدول operations نفسه — **وهذا هو إصلاح اليومين المدموجين
معاً**: رسالة تأكيد صريحة قبل التنفيذ، ثم تدقيق `rebuild_reports`، ثم رسالة
نجاح بكم حركة أُعيد توزيعها وكم يوماً تأثر. واليوم المفتوح الحالي لا يُقفل

**6) زر «✏️ تعديل الحركة» بشريط عمليات اليوم 📝**: للأدمن والمدير فقط
حصراً بالدور (لا يظهر للبائع نهائياً حتى لو كان هو من سجل الحركة — وصلاحية
«تصحيح عملية» القائمة للإصدار 18 شيء منفصل بجانبها كما هي بلا أي مساس)،
وعلى حركات اليوم التجاري المفتوح فقط: نافذة RTL بجميع الحقول معبأة

= الكمية × السعر ولا يُدخل يدويًا** (والمرتجع يُخزَّن سالباً كما يُخزَّن
دائماً)، وقبل الحفظ رسالة تأكيد تعرض **القيمة القديمة ← الجديدة لكل حقل
معدّل**، وبعده: تحديث الصف فوراً + تدقيق `edit_operation` بالقيم كاملة +
تحديث المجاميل فوراً — ولا يُمس daily_reports للأيام السابقة إطلاقاً
(تقرير اليوم الحالي يتأثر تلقائيًا لأن الإغلاق يحتسب من operations).

يدوي) وفتح يوم جديد، من الدالة المركزية نفسها.

## 🔧 إصلاح قناة التحديث — بلا توكن مضمّن نهائياً (الإصدار 22)

### ما الذي حدث ولماذا توقفت التحديثات؟

فحص التحديثات كان يرفق توكن GitHub داخل كل طلب يرسله البرنامج
للمستودع، وذلك التوكن كان مضمّناً في main.py المنشور في مستودع عام —
فاكتشفته خدمة Secret Scanning في GitHub وأبطلته تلقائياً (سلوكها
الموثق مع أي توكن مكشوف في مستودع عام). وأي طلب يحمل توكناً ملغى
يُرفض بالكامل (404) حتى لو كان الملف المطلوب عاماً متاحاً للجميع،
فصار كل جهاز يرى «تعذر الاتصال — تحقق من الإنترنت» عند فحص التحديث
رغم أن الإنترنت سليم تماماً. والنتيجة: قناة التحديث ماتت لكل
الإصدارات المنشورة (2.1 حتى 2.11) بلا استثناء.

### الإصلاح الدائم (سطر واحد + تعليق شارح)

- `GITHUB_TOKEN = ""` — التوكن صار فارغاً دائماً: الفحص والتنزيل
  و«ما الجديد؟» تعمل بطلب مجهول عادي عبر المستودع العام — المسار
  القائم أصلاً في `_update_headers` منذ الإصدار 10 (الفراغ = بلا

## 🧭 محطة حركات الأيام الكاملة — مشاهدة وتعديل وإضافة وحذف (الإصدار 23)

### ما الجديد في نافذة «حركات الأيام السابقة»؟

النافذة القائمة (قراءة فقط من الإصدار 21) صارت **محطة مشاهدة وتعديل
كاملة** للأدمن والمدير — والبائع لا يراها نهائياً كما كان دائماً:

- **صف اليوم التجاري الحالي أعلى القائمة** بعنوان «اليوم الحالي (لم
  يُغلق بعد)» مميزاً بلون أخضر فاتح، ومجاميله حية من عملياته نفسها —
  وتحته الأيام المغلقة من الأحدث للأقدم كما كانت تماماً.
- **ثلاثة أزرار** تعمل بعد اختيار يوم (والإضافة تحتاج اليوم فقط):

| الزر | يعمل على | وقته المسجل | بعده فوراً |
|---|---|---|---|
| ➕ إضافة حركة لهذا اليوم | أي يوم (حالي أو سابق) | اليوم الحالي: الآن / يوم سابق: 12:00 ظهراً من يومه | اليوم المغلق: إعادة احتساب صف تقريره — اليوم الحالي: تحديث العدادات |
| ✏️ تعديل الحركة المحددة | حركة أي يوم بعد اختيارها | وقتها الأصلي لا يتغير | نفس القاعدة + تأكيد بالقديمة والجديدة لكل حقل |
| 🗑️ حذف الحركة المحددة | حركة أي يوم بعد اختيارها | يُعرض في التأكيد | نفس القاعدة + نقل لسلة المحذوفات بمرجع يومها |

- **الحذف ليس مسحاً نهائياً**: نفس آلية الحذف القائمة تماماً (recycle_add
  إلى deleted_operations مع من حذفها ومتى) — والاستعادة تعمل كما كانت.
- **التدقيق موقّع في السلسلة** بأحداث جديدة: add_operation و
  edit_operation وdelete_operation — باليوم المتأثر والدور والقيم
  القديمة والجديدة كاملة.
- **زر «🛠️ إعادة احتساب وتوزيع حركات هذا اليوم» للأدمن وحده كما هو
  تماماً** لم يُمس (والمدير لا يراه كما كان دائماً).

### زر «✏️ تعديل الحركة» في الشاشة الرئيسية

الزر الموجود بجانب جدول عمليات اليوم (من الإصدار 21) صار يفتح **نفس
نافذة التعديل المركزية نفسها** المستخدمة في المحطة — نافذة واحدة
ومنطق واحد بلا أي تكرار كود، والدوال القديمة باقية كما هي لم تُحذف.

### القاعدة الدائمة في هذه الجولة

كل الإضافات في دوال جديدة مستقلة لا تُلمس أي دالة قائمة — والاستثناء
المصرح به الوحيد في الكود القائم: ختم VERSION من 2.12 إلى 2.13 لنشر
التحديث عبر النظام القائم نفسه. والاختبارات: وحدة الجولة 23 كاملة
(101 فحصاً) + البطارية الكاملة لكل الجولات 2→23 (**1933 فحصاً كلها
خضراء**) — بلا أي فشل واحد.
